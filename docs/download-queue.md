# 持久化下载队列

单曲“保存到本地目录”和“批量下载”先将整批歌曲写入 SQLite `download_tasks`，提交成功后才提示已入队。下载由服务端单个工作线程按入队顺序执行，页面关闭、翻页和切换歌单不会丢失已提交的任务。后续批次会追加到队列；相同音源、歌曲 ID 和目标目录的活动任务不会重复入队。

应用启动并成功监听端口后，会将上次处于 `downloading` 的任务恢复为 `waiting`，继续处理等待队列。中断歌曲重新下载，暂不支持音频字节断点续传。歌曲已保存但任务状态未提交时，现有文件去重检查会避免再次下载。文件使用临时文件写入并原子重命名，避免中断写入留下被当作成功的半成品。

右侧“下载管理”入口显示活动任务数量。队列页展示总体已处理数量、成功/跳过/失败统计、各首歌曲状态、目标路径和错误信息，每两秒刷新。可按状态筛选、分页、取消等待任务或重试失败/取消的任务。历史记录单独保留。关闭管理面板不会停止下载。

“全选”仍只选择当前页面。用户需逐页追加，确认框和入队提示显示实际提交数量。旧版从未写入数据库的内存任务无法自动恢复，需要重新选择提交。

队列保存入队时的目录、文件名模板和元数据嵌入选项；后续修改设置不会改变已入队任务的保存位置。WebDAV 同步使用执行时配置，同步失败作为警告显示，本地成功文件不会丢失。

## 验证

- `go test ./core ./internal/web ./internal/appshell`
- `go test -race ./core -run TestDownloadQueue -count=1`
- `node --test tests/batch-download.test.cjs`

覆盖 550 首整批持久化、数据库重新打开、下载中任务恢复、先进先出、执行期间追加、失败状态、取消/重试、并发提交去重、跨站写入拒绝以及确认/取消下载。

## 整张专辑 / 整个歌单

专辑、歌单卡片及详情页提供“下载整张专辑 / 下载整个歌单”。此入口提交容器标识，由服务器重新获取全部曲目后，整批加入持久化队列，不依赖页面复选框和分页。支持远程歌单、专辑、本地自建歌单及外部导入条目。本地音频无需重复下载；已在活动队列的歌曲会去重，并显示实际获取、新增及跳过数量。

普通手动提交每批最多 2000 首；整单入口最多 20000 首，超出会明确报错且不部分入队。平台获取失败也不会将不完整结果当作成功加入队列。
